# updev v0.7.15

`updev v0.7.15` is a drift-prevention and routed-UX hardening patch for the
macOS/Homebrew/mise public preview. It keeps the `v0.7.x` support boundary and
focuses on making daily review loops more predictable before widening provider
support.

Highlights:

- `updev doctor dependencies` now reports whether the current shell exported
  the optional `UPDEV_BREW_WRAPPER` marker and whether `[brewfile].write_mode`
  enables updev-managed Brewfile writes. Inactive wrapper/write-boundary checks
  are optional diagnostics, not hard failures.
- Homebrew 6 trust diagnostics now group untrusted entries by tap, avoid
  prompting already trusted formula/cask targets again, and show a tap-scoped
  repair command for each affected group.
- Strict Homebrew update gating now honors Homebrew's trust state, so trusted
  non-official tap candidates are not skipped solely for tap provenance review.
- The Homebrew dependency JSON probe suppresses auto-update before running
  `brew outdated --json=v2`, so progress logs do not corrupt the JSON contract
  check.
- Strict Homebrew updates now refresh Homebrew metadata and then re-probe
  `brew outdated --json=v2 --greedy` before item-scoped apply/hold decisions,
  so newly discovered formula/cask candidates are not hidden by stale safety
  cache entries after `brew update`.
- The Homebrew wrapper no longer guesses a profile category for non-TTY
  `brew install` or `brew tap`. TTY sessions prompt from the desired Brewfile's
  detected categories; non-TTY callers must set `UPDEV_BREW_CATEGORY` when the
  manifest is categorized before the real brew command runs.
- Homebrew drift adoption now syncs the rendered home `Brewfile` after
  confirmed `Brewfile.tmpl` mutations, refreshes the routed TUI report and
  inventory cache, and also repairs stale rendered Brewfiles when the source
  entry already exists.
- Brewfile adoption now recognizes compound profile guards such as
  `if or (has "work" .profiles) ...` generically, so TUI drift actions can
  write into baseline profile blocks instead of requiring a single exact
  `if has "<category>" .profiles` form.
- Brewfile adoption no longer assumes chezmoi profiles are present. It also
  supports generic `# updev: category <name>` markers and uncategorized
  Brewfiles, where the confirmed adoption action appends to the manifest.
- When a rendered `~/Brewfile` is the active desired state, entries that only
  exist in the source template are shown as `profile-mismatch` for any source
  category instead of being offered as fresh adoption candidates.
- Confirmed Homebrew drift actions now show a result detail screen with the
  exact provider token, category, changed files, diff, validation status, and
  rollback command, making similar casks such as app and CLI companions easier
  to distinguish.
- Homebrew cask failures where the app artifact is missing are now shown as
  item-level errors instead of being split into a misleading `updated` item plus
  a provider-level error.
- Release automation stays on GoReleaser with local `goreleaser-check` and
  `goreleaser-snapshot` gates, GitHub artifact attestations, and installer
  checksum compatibility.
- Cached `updev last` update-result rows compact Homebrew
  `most recent version ... not installed` warnings into item-scoped rows, with
  Japanese text in Japanese terminals.
- Routed TUI dogfood continues to target low-step navigation across `updev`,
  `updev last`, `updev list`, `updev hub`, update evidence, security review,
  manual review, backend convergence, and policy review.

Validation:

- `mise -C tools/updev run check`
- `mise -C tools/updev run docs-check`
- `mise -C tools/updev run goreleaser-check`
- `mise -C tools/updev run goreleaser-snapshot`
- `git diff --check`
- `chezmoi apply --dry-run`
- Real TTY dogfood covers the routed review surfaces before tagging.
